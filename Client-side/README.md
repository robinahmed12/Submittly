# Submittly — Frontend

Next.js 16 (App Router) client for Submittly. Serves two personas against the
Submittly Express API:

- **Student Portal** — submit a project, track its review status.
- **Mentor Review Dashboard** — paginated submissions, status filters, approve/reject, stats.

> **Spec:** [`../Docs/submittly_project_requirements.md`](../Docs/submittly_project_requirements.md)
> **Implementation plan:** [`docs/implementation-plan.md`](./docs/implementation-plan.md)
> **Coding style:** [`docs/coding-style.md`](./docs/coding-style.md) — binding for every PR.

## Requirements

- **Node.js 20.9+** (Next.js 16 minimum)
- The Submittly API running locally — see [`../Server-side`](../Server-side)

## Setup

```bash
# 1. Install
npm install

# 2. Configure
cp .env.example .env.local
# then edit .env.local if the API is not on http://localhost:4000

# 3. Run
npm run dev
```

The app is served at <http://localhost:3000>.

### Running alongside the backend

The client talks to the API through a server-side proxy, so **CORS is never
exercised** by the browser. Start the API first:

```bash
cd ../Server-side
npm install
npm run prisma:migrate   # once, to create the schema
npm run prisma:seed      # optional: creates the ADMIN and MENTOR accounts
npm run dev              # API on http://localhost:4000
```

Then start this app in a second terminal.

## Environment variables

| Variable  | Required | Visibility  | Purpose                                                   |
| --------- | -------- | ----------- | --------------------------------------------------------- |
| `API_URL` | yes      | server-only | Base URL of the Express API, e.g. `http://localhost:4000` |

`API_URL` is read **only** by the proxy route at
`src/app/api/backend/[...path]/route.ts`. It is never exposed to the browser.
There are currently **no `NEXT_PUBLIC_` variables** — anything added with that
prefix is public by definition and needs a security review.

Copy `.env.example` to `.env.local` for local work. `.env*` files are
git-ignored; `.env.example` is committed.

## Architecture at a glance

```
Browser ──/api/backend/*──▶ Route Handler proxy ──Bearer──▶ Express API (:4000)
   │                              │
   │                       reads/writes httpOnly cookies
   ▼
TanStack Query (client state) + Server Components (page shells)
```

- **`src/proxy.ts`** — Next 16's renamed `middleware.ts`. Gates routes by role
  (UX only; the API is the real authority).
- **`src/app/api/backend/[...path]/route.ts`** — the only code that talks to the
  Express API. Attaches the `Authorization: Bearer` header server-side and
  stores the token in an httpOnly cookie, so the token never reaches browser
  JavaScript.
- **`src/features/<feature>/`** — vertical slices: `api.ts`, `keys.ts`,
  `schemas.ts`, `types.ts`, `components/`, `hooks/`.
- **`src/components/ui/`** — shadcn/ui components, generated by the CLI.
  **Do not edit them by hand.**
- **`src/components/shared/`** — app-wide composites only.

## Adding a shadcn/ui component

```bash
npx shadcn@latest add <component>
```

The CLI writes real source into `src/components/ui/`. Customise it by wrapping
it in `components/shared/` or `components/features/`, or by adding a `cva`
variant — never by editing the generated file.

> shadcn/ui v4 replaced the old `Form` component with `<Field>` primitives
> (`Field`, `FieldLabel`, `FieldError`, `FieldGroup`, …). Forms use
> react-hook-form's `useForm` + `zodResolver` with `<Controller>`.

## Notes

- `package.json` pins `effect` via `overrides`. `@hookform/resolvers@6` declares
  an optional `effect@^4` peer that conflicts with the `@typeschema` chain's
  `effect@^3`. The zod resolver does not use `effect` at all; the pin satisfies
  the packages that are actually installed.
- `next.config.ts` leaves `cacheComponents` off. The app reads cookies for the
  session and leans on TanStack Query for interactivity, so the default dynamic
  rendering model is the predictable fit.
- `npm audit` reports a high-severity advisory in `braces`, reachable only
  through `eslint-config-next` → `fast-glob`. It is dev-only, and the upstream
  fix downgrades `eslint-config-next` to v14, which breaks the Next 16 setup.
  It is not auto-fixed for that reason.
